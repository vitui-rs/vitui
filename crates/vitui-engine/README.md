# vitui-engine

Cells, surfaces, layers, compositing and damage tracking for terminal rendering.

**Nothing is published. The version is `0.0.0` and there is no stability promise before 0.x.**

Everything that touches the terminal, and nothing above it. An application that wants fast layered
output and brings its own layout can depend on this crate alone and never meet a layout type — which
is the point of the split, not a side effect of it.

```rust
use vitui_engine::{Color, Config, Engine, Rect, Style};

let (mut screen, _wake) = Engine::new(Config::default()).attach()?;
let (w, h) = screen.size();

let layer = screen.layers().add_content(0, Rect::new(0, 0, w, h), true);
if let Some(mut view) = screen.layers().view(layer) {
    view.text(1, 1, "hello", Style::new().fg(Color::indexed(4)));
}

// The verbs marked their own damage as they wrote, so this frame has something to send; a
// `present` with nothing drawn between the two sends nothing at all.
screen.present();
```

## What it will not do

Each of these is a decision with a measurement behind it, not a gap.

- **It does not lay anything out.** Callers bring rectangles. No layout concept may enter through the
  `Surface` API — that is the door this erodes through.
- **It never iterates your data.** It offers clipping and offset viewports; culling is yours.
  Invariant: *frame cost is proportional to visible cells, never to data volume.*
- **crossterm is invisible.** Input and terminal mode only, never output, and never in a public
  signature.
- **No traits in the public surface, and `#![forbid(unsafe_code)]`.** The engine has nothing to call
  upward, so the dependency arrow is enforced by there being no arrow.
- **No cell, grapheme handle or style bit is readable from outside.** Which is why the oracle
  that checks the picture lives inside the crate rather than in a caller's test.

## Status

Implementation-complete, with every property it claims wired to something that fails when the claim
stops being true. The thing worth knowing before you depend on it: **Windows has never been run.**
Every green run behind the numbers here is one machine, one OS, one architecture.

Beside the gates inside the crate is a conformance suite that asks a real terminal rather than this
crate's model of one — Ghostty, kitty, WezTerm, Alacritty, iTerm2, Terminal.app and tmux, each with
a committed report. It is where four of the eight quirk-table entries come from. Windows Terminal is
the one supported terminal nobody has driven through it, so what this crate believes about it is
inference. The MSRV is 1.88, verified by a CI job pinned to it rather than declared.

## Dependencies

crossterm, plus UCD tables generated by this crate's own build script. That is the whole list, and
`deny.toml` at the repository root is what keeps it that way.

## Documentation
